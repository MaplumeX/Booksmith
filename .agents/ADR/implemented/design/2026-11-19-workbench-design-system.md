# ADR: Workbench design system — press-proof desk

Status: implemented

## Problem

Booksmith 是一个新界面，仓库里没有任何设计系统、组件库或 token 文件，一切从零。使用场景是
长时间盯着代码与渲染结果的校对工作：屏幕被切成结构、文本、预览三块，两侧长时间停留，
眼睛在等宽代码与纸面预览之间来回跳。这类工作台最怕的不是"不够现代"，而是**层级噪声**：
一堆卡片、阴影、圆角、彩色状态条会让"哪一块是当前焦点"变得需要辨认。

已用脚本核实的两组硬约束：

- 真实书正文区域是书中 CSS 决定的（`body { margin: 5% }`），编辑器的 UI 不能与预览争夺注意力。
- 中文正文在 `1440px` 下必须限宽，预览列固定 `400–560px` 才能模拟阅读器版心。

## Decision

**定调三行**

- **Visual**：一张印刷校样台 —— 冷灰纸面、`1px` 分割线替代阴影、单一墨蓝强调色，密度紧凑，
  像排版工具而不是 SaaS 后台。
- **Content**：顶栏（身份 + 主操作）→ 三栏工作区（结构 / 文本 / 渲染）→ `28px` 状态栏
  （文件、字数、保存态）。无卡片、无营销区、无居中英雄区。
- **Interaction**：预览 `300ms` 防抖跟随编辑；分栏可拖拽（预览 `400–560px` 夹紧）；保存反馈
  走状态栏一行字 + 顶栏脏标记，不用 toast 打断输入。

**`neutral-500 (#69778c)` 在 `#fbfbfa` 上只有 4.39 —— 只允许用于图标与禁用文字，永不承载正文。**

代码高亮自成一档，随主题切变量：`--cm-tag`（`#2b5277` / `#93b8dd`）、`--cm-attr`
（`#8a5a12` / `#dcb877`）、`--cm-string`（`#2c5b39` / `#a8cdb4`）、`--cm-comment`
（`#546175` / `#8896aa`）、`--cm-keyword`（`#224262` / `#b8d0e8`）、`--cm-number`
（`#a0562a` / `#e0a97c`），全部在 `--surface` 上 ≥4.5。

**刻度**

- 字号 `12 / 13 / 14 / 16`：UI 13，代码 13 等宽；行高 UI `1.45`，中文正文 `1.6–1.75`。
- 字体：UI `-apple-system, "Segoe UI", "Noto Sans SC", sans-serif`；代码
  `ui-monospace, SFMono-Regular, Menlo, Consolas, "Noto Sans Mono CJK SC", monospace`。
- 间距 `4 / 8 / 12 / 16 / 24`；控件高 `26 / 30 / 36`；顶部栏 `44`、状态栏 `28`、文件树 `240`。
- 圆角只有 `4px` 一档；**不使用卡片阴影**，层级靠表面色阶与 `1px` 边框。
- 焦点：`:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px; }`。
- 动效：仅 `transform` / `opacity`，`150–200ms`；`prefers-reduced-motion` 下只保留透明度。
- 主题：`data-theme` 由 `prefers-color-scheme` 驱动，只切语义别名。

**布局**：`100dvh` 三段式；三栏 `240px / flex / 400–560px`（可拖拽，夹在 400–560）。
主代码区不限宽（代码编辑器属例外）。`<1024px` 时文件树与右栏都变成覆盖式抽屉，由顶栏
「文件」「预览」按钮切换——否则 400px 视口下编辑器只剩 160px。书库页封面卡 `160×220`，
网格间距 `24`，容器 `max-width: 1120px`。

**右栏五个 tab**：预览 / 查找 / 元数据 / 目录 / 版本。每个 tab 内部独立滚动，不改变三栏宽度。

## Alternatives considered

**方案 2 · 双模切换（文件树抽屉 + 编辑/校对两种全屏模式）**。布局更宽裕，适合小屏，但"书的
全景"平时不可见，切文件多一步；EPUB 恰恰需要结构常驻视野。否决。

**方案 3 · 图标栏 + 可停靠面板（IDE 味）**。功能多时最好扩展，但 MVP 只有目录/元数据两块，
图标栏会空一半并要求二级导航。作为将来的演进方向保留。

**书库页做成清单表格（每行显示章节数/大小/时间）**。信息密度高，但书的实体感消失，且与
编辑器工作台的"工具感"重复。改为封面卡 + 一行信息，超 50 本再给列表。

**Tailwind + shadcn/ui**。生态成熟，但会引入一套与工作台不匹配的默认视觉，且本项目组件数量
少（约 12 个），手写 CSS 变量更短。不采用，`tokens.css` 与 Tailwind 的 `@theme` 映射方式在
将来需要时可加。

**右栏保持三 tab（预览 / 元数据 / 目录）**。实现中版本没有别的入口，Q9=B 又承诺了可回滚，
于是加了第四个 tab；查找也放进右栏成为第五个。三个以上 tab 都在同一行、不换行，440px 下
仍可点击。

**仅浅色 / 仅暗色**。校对工作常在夜间，跟随系统是零成本的正确默认。

## Consequences

**验收结果（2026-11-19）**

- `tokens.test.ts` 守卫 16 组配对（浅/暗各 5 组 + 状态 3 组 + 代码高亮 6 组），全部 ≥4.5；
  故意把 `--text` 改浅会让其中 2 个失败。
- `e2e/audit-shots.mjs` 在 1440 与 400 两档对登录、书库、空态、错误态、编辑器、暗色出图，
  无横向溢出、无断图、无 console 错误。
- 窄屏三栏改为「编辑器铺满 + 两个抽屉」，400px 下编辑器宽度从 160px 恢复到 400px。

**代价与已知限制**

- 单色强调 + 无阴影在低对比显示器上可能显得"糊"；只允许加深 `--border-strong`，不引入阴影。
- 右栏五个 tab 在 `1024–1200px` 宽度下会被挤到需要横向滚动；接受。
- 暗色模式下预览仍是书自己的白底（书的 CSS 未定义暗色），这是刻意保留的"模拟阅读器"行为。
- `DESIGN.md` 的组件索引需要随新组件手动更新，没有自动校验。
