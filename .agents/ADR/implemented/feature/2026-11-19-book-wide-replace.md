# ADR: Book-wide replace with an undoable batch

Status: implemented

## Problem

查找能覆盖全书，替换只能覆盖当前文件。`apps/web/src/ui/SearchPanel.tsx` 的每个命中只是一个
跳转按钮；真正的替换走 `@codemirror/search` 的 ⌘F 面板，作用域是当前 `EditorState`。

校对时的真实动作是跨章节的一致性修改：「把 23 章里所有 `<i>马克思</i>` 统一成
`<em>马克思</em>`」「把 `class="figure"` 批量改成 `class="fig"`」。现在只能一章一章地做，
23 次操作里漏一次就是一个不一致的书。

## Decision

**替换作用于当前搜索结果集，走确认步，留一个批次快照。**

- `planReplace(files, { query, replacement, regex, caseSensitive })` 返回每个文件的编辑列表与
  总替换处数；正则模式支持 `$1` / `$&` 捕获组引用；非文本条目与不可编辑条目直接跳过。
- `SearchPanel` 在「查找结果」之上加一个替换输入与「替换全部」按钮，执行前显示
  `将替换 384 处，涉及 23 个文件`，确认后执行。
- 执行后 `SearchPanel` 保留一行 `已替换 384 处 · 撤销`。撤销把每个文件恢复成替换前的文本。

**撤销是批次快照，不是 CodeMirror undo。** 每个文件是独立的 `EditorState`，未打开的文件根本
没有 view，CM 的 undo 无法跨 view 表达一次批量操作。声称「一次 ⌘Z 撤销全部」会是空头承诺。
批次快照是同一个产品语义（一次操作、一次回退），机制放在 `SearchPanel` 手上。

**已打开的文件同步显示**：替换后对每个受影响的打开文件调用
[每 tab 一份 editor state](../bug-fix/2026-11-19-editor-state-per-tab.md) 的 `content` prop 同步，
让代码区立刻显示新文本；该文件自身的撤销栈被清空（外部改写不是可递增的编辑）。

## Alternatives considered

**把所有受影响的文件临时创建 `EditorState`，用 CM transaction 施加编辑，再一次性提交。**
这样每个文件都有自己的撤销栈，但依然无法「一键撤销全部」——用户要按 ⌘Z 23 次。而且为 23 个
文件建 state 只为做一次替换，开销远大于文本替换。

**直接覆写文本，不留回滚。** 最简单，但 384 处替换一旦写错（正则贪婪、捕获组写反），用户唯一
的退路是逐文件翻快照。留一个批次快照的成本只是一个 `Map<path, string>`。

**逐文件确认。** 遵守「批量操作要可审阅」，但 384 处逐个确认等于不做批量。确认步放在总数上，
细节可回滚，是批量的正确粒度。

**替换只在当前文件（现状）也算能用。** 那就等于不解决跨章一致性问题，而这正是校对的主要工作。

## Consequences

**交付实测（2026-11-19）**

- 真实书「马克思」→「马克斯」：428 处 / 25 个文件，保存 v2 后重载搜索原词为 0 处。
- 一键撤销把全部受影响文件恢复为替换前文本，状态栏回到「未修改」。
- `$1` / `$&` / 大小写 / 非法正则 / 0 匹配由 9 个单测覆盖，跨文件替换与撤销由 3 条 e2e 覆盖。

**已接受的代价**

- 正则替换在 `.xhtml` 上横跨标签时会产生非法标记（例如匹配到 `<p>…</p>` 的中间）。这不是
  替换层能拦住的，检查面板（[结构检查](2026-11-19-structure-check-panel.md)）与
  保存校验是兜底。
- 批次快照只活在该 `SearchPanel` 实例的生命周期里；刷新页面后不可撤销（此时应依赖快照历史）。
