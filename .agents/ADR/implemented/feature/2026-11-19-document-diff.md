# ADR: Source-level snapshot diff

Status: implemented

## Problem

> 以下描述的是本次改造之前的实现状态。


有了快照时间轴，还需要能看见「两版之间改了什么」，否则恢复是一次盲选。当前没有任何 diff 能力：`GET /api/books/:id/versions` 只返回版本号、体积与时间。

三个约束决定这个 diff 不能直接照搬代码工具的做法：

- 一本真实书有 28 个正文文件，一次保存通常只动 1–3 个。按文件铺开 diff，用户得先自己找哪里变了。
- 全书正文几十万字，直接上字符级 diff 会卡死主线程。
- 使用者给出的定位是「文档级」：一本书就是一个文档，diff 不该暴露「第 3 个 xhtml 文件」这种内部结构。

## Decision

**把一本书拼成一份源码文本，在这份文本上做行级 diff，按源码呈现。**

- **拼接**：按 `pkg.spine` 的阅读顺序（`manifest` 把 idref 映射成 path），每章原文前插一行 `<!-- EPUB/text/ch003.xhtml -->` 注释。没有这行注释，28 个文档的堆叠无法定位；有了它，读者仍能知道改动属于哪一章。
- **对齐**：两版的行序列先裁剪公共前后缀，再对其余部分做 LCS。裁剪是关键——两版通常只差几行，这一步让 LCS 只看到真正变化的部分。
- **内联**：相邻的「1 删 + 1 增」合并成一个 `changed` 行，对其做字符级 diff。xhtml 里一个段落常常是一整行，没有这一步，改一个标点就会整行标红。
- **呈现**：等宽字体、逐行渲染、行首一列符号（`-` / `+` / `~` / 空），删除行红底带删除线，新增行绿底带下划线。

**用源码而不是渲染态，是这份决策的核心。** 渲染态在「看排版对不对」时更直观，但它看不见任何非文本变化：改了 `class`、换了图片路径、改了 `<section>` 的 `epub:type`、改了 OPF 的元数据，在渲染结果里全都看不出来。而使用者恢复快照的最初动机正是「改坏了」——一本书「改坏了」的多数形态是结构而不是错别字。

**不用 iframe。** 源码视图只渲染文本节点，React 自动转义，不存在把书的 HTML 注入主文档的路径。`PreviewPane` 的 iframe 隔离是为了渲染真实 markup，这里不需要。

**非正文改动只列一行摘要。** 比对两版 archive 里非 spine 的文本文件（`css` / `opf` / `ncx` / `xml` / `svg` / `js`），末尾显示「另改动：content.opf、OEBPS/style.css」——只列文件名，不展开。

**对比基准是当前版本。** 点开历史的目的是决定要不要恢复，需要的是「这版和现在差在哪」。

## Alternatives considered

**渲染态 diff（用书的 CSS 渲染成连续页面，在正文上标出增删）。** 这是最初实现的版本，被使用者否掉：它看不出标签、属性、样式与元数据的任何变化，而这些恰恰是「改坏了」最常见的形态。它唯一的优势是「像看一份文档」，代价是把结构变化全部隐藏。本次决策取代它。

**双栏并排 diff（IDE 心智）。** 需要 `@codemirror/merge`，为「看一眼」起两个编辑器实例去对齐 174 KB 的章节不划算，而且双栏在「文档级」语境下会让读者同时看两份完整文档。

**文件级摘要 + 下钻（先列「改动 3 个文件」，点一个才看该文件的 diff）。** 这是最初的推荐，被「文档级」这个定位直接否掉：它把「一本书」重新暴露成 28 个文件。代价是丢失了「哪些章节改了」这个快速概览，且不能按文件跳转。当前方案用章节注释行缓解。

**块级对齐（把 body 切成 `p` / `h1` / `li` 等块，块级 LCS 后再字符级对比）。** 它是渲染态版本的骨架，能正确跳过含内联标记的段落而不会把 MathML 渲染成乱码。源码视图下块级对齐是多余的：行就是天然的切分单位，且不需要解析 XHTML。

**单趟全书字符级 diff。** 几十万字规模下会让主线程卡死。

## Consequences

**验收结果（2026-11-19）**

- 未改动的行原样输出，行首只有一列空符号。
- 「1 删 + 1 增」合并为一个 `changed` 行并做字符级对比：在真实书上把「不会」改成「未必会」，只有那个词被标出。
- 属性改动可见：`class="level2"` → `class="level2 revised"` 在源码视图里高亮，这是渲染态做不到的。
- 整章新增或删除时该章所有行以单一颜色呈现（单测覆盖）。
- 行顺序严格按 `pkg.spine`；每章之前出现一行 `<!-- EPUB/text/chNNN.xhtml -->`。
- 非正文文件有改动时出现文件名摘要，无改动时不出现。
- 打开快照后自动滚动到第一处变化。
- 真实书全量 8202 块 / 约 700 KB 源码，渲染与滚动无卡顿（Chromium，1440px 与 400px）。

**代价与已知限制**

- 行级 diff 在「整段被重排」时会产生大量红绿行；章节注释行能帮助定位，但没有折叠未变区域的能力。
- 拼接后的源码不是合法 XHTML（多个根元素），只用于显示，不能拿去校验或保存。
- 每次打开一个快照要下载该版整包（约 2 MB）。目前按需加载、无缓存，重复打开同一个快照会重复下载。
- 全书 8000+ 行的 DOM 一次性渲染，没有虚拟化。2 MB 级书流畅，合订本级别的 EPUB 会明显变慢。
