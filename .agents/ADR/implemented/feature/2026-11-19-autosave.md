# ADR: Autosave with a two-layer durability model

Status: implemented

## Problem

使用者要两件事同时成立：**防丢**（误关标签、崩溃、忘记按 ⌘S）与**省手**（不希望每次改动
都手动保存）。交付前两者都做不到：改动只活在内存的 `texts` 与 `dirty` 里，`beforeunload`
只能弹一次浏览器原生确认，用户点「离开」就没了。

直接加定时器会被两条约束挡住：

- 每次保存是整包 `PUT`：2.1MB 写入 + `ingestEpub` 全量校验。三秒一次的自动保存是三小时 5GB
  级写入。
- [旧记录](2026-11-19-snapshot-history.md) 明确否决过「编辑静默 60 秒自动生成快照」，理由是
  2.1MB × 50 次/会话，且 `TOTAL_CAP = 40` 会让自动版本在二十分钟内清空真实历史。

[页面级快照记录](2026-11-19-page-level-snapshots.md) 改变了成本结构：一条快照是一个条目
（几十 KB）而不是整包，历史不再被自动保存挤空。剩下的问题全部是节奏与语义。

## Decision

**持久性分两层，两层解决不同的损失。**

- **本地层**：停手 1 秒后把 `dirty` 里的文本写入 IndexedDB（`apps/web/src/state/draftStore.ts`，
  只存改过的文件，通常 <200KB），保存成功后清除。这一层负责浏览器崩溃、误关标签、误刷新。
  每次读写都是 best-effort：浏览器拒绝 IndexedDB 时编辑照常进行，只是退回单层。
- **服务端层**：停手 **20 秒**触发保存；两次服务端保存之间至少间隔 **3 分钟**（地板）；切换
  到别的书、组件卸载时补一次。这一层负责换设备、换浏览器、机器损坏。

三小时连续编辑对应约 60 次整包上传（≈126MB），而页面历史只增加真正变过的条目。节奏由
`apps/web/src/state/autosave.ts` 的纯调度器实现（注入 `now()`，单测覆盖防抖、地板、
`flush` 与 `cancel`）。

**手动保存不消失，但不再是唯一入口。** ⌘S 与「保存」按钮立即保存，并带
`x-booksmith-checkpoint: manual` 头，绕过下面那条窗口强制落一条快照。历史里不区分手动与
自动来源——使用者选择单层历史，不为自动版本单独标记或隐藏。

**同一文件十分钟窗口内不新增快照行。** 变化的内容本身已经在当前整包里，窗口内跳过只是让
历史更接近「可辨认的编辑阶段」而不是「每一次停手」。跳过发生在服务端：它知道该路径最新一条
快照的时间。窗口不影响版本号与当前内容。

**没有真实变化就不写入，三道闸**：客户端 `dirty.size === 0` 不发请求；服务端在整包 sha256
与 `book_files.sha256` 相同时返回当前版本号、不写行、不递增 `current_version`；页面快照只对
字节变化的条目创建。

**失败必须被看见，且不替人做覆盖决定。** 网络失败或 5xx：停住自动保存，顶栏状态转为
「保存失败 · 重试」（文字 + 颜色，不单靠颜色表意）。409（别处已保存）：沿用现有冲突横幅，
自动保存暂停到用户重新加载——`save()` 在 `conflict` 为真时直接返回，避免每三分钟重放同一次
409。不做静默重试，也不做跨标签单写者租约。

**状态常驻可见**：`N 处未保存` / `保存中…` / `已保存 HH:MM` / `保存失败 · 重试`。

以上取舍与三处公开的成熟做法一致：Apple `NSDocument` 的 autosaving in place 是原地覆盖当前
状态、版本由系统另外稀疏创建；Notion 的版本是「编辑中每 10 分钟一条、最后一次编辑后 2 分钟
再一条」的时间节流，与内容同步分开；GitLab Pajamas 要求输入停止后短防抖保存、状态常驻、
失败用常驻 inline 提示并给重试。VS Code 的 Hot Exit 是本地崩溃缓冲的现成先例。

## Alternatives considered

**自动保存即每次生成一个整本版本。** 实现最小（复用现有 `PUT`），但必须在二十分钟内清空
`TOTAL_CAP = 40`，等于用自动保存杀掉版本功能。旧记录已经否决过一次，本次不重开。

**给版本加 `source: manual | auto` 列，自动版本只保留最新一条（双层，Apple 式）。** 本次规划
最初的推荐：历史干净、存储有界、⌘S 仍是里程碑。使用者选了单层——既然页面级快照已经把单条
成本降到几十 KB，就没必要再为「自动 vs 手动」维护一套语义与一条剪枝规则。

**复用已有的 `note` 列存 `auto` 当来源标记。** 零迁移，但 `note` 同时承载恢复流程写入的
`restored from vN`，机器判断与给人看的文本挤一列。选定单层之后这一项整体不需要了。

**只做本地草稿，服务端保存仍然手动。** 崩溃与误关能兜住，零服务端改动。但用户要的「省手」
没有满足。

**单层、服务端更勤（停手 3 秒落库，不走本地草稿）。** 丢失窗口 3 秒，但三小时 380MB 级写入
与数百次整包校验，且每次崩溃都可能撞在写入中途。

**单层、Notion 式稀疏（每 10 分钟 + 停手 2 分钟，不做本地草稿）。** 写入最省（约 50MB），但
一次浏览器崩溃最多丢十分钟校对。

**每 N 秒无条件 `PUT`。** 制造大量内容未变的空转写入，正是要避免的。

**BroadcastChannel / Web Locks 单写者租约，避免两个标签同时自动保存。** 能从源头减少冲突，
但它与 `ETag` 是两套真相，租约失效时反而更难解释。409 + 横幅已经足够且更诚实。

**指数退避自动重试。** 网络抖动可以自愈，但真实 409 会被重试掩盖，最终仍要弹横幅。

**窗口内覆盖上一条快照（只留窗口末态）。** 历史更短，但中间的编辑阶段连同它们的 diff 一起
消失，与「按时间浏览」的定位冲突。

## Consequences

**验收结果（2026-11-19）**

- e2e `saves by itself once typing stops`：停手约 20 秒后顶栏出现「已保存 HH:MM」、版本 +1；
  之后 5 秒内没有新改动时版本保持不变。
- e2e `brings back an unsaved draft after a reload`：改字后 1.5 秒刷新，横幅给出本地草稿，
  恢复后内容回编辑器且重新进入未保存态。
- 服务端 `skips a second snapshot for the same entry inside the ten minute window`：窗口内保存
  只更新当前整包、不写快照行；`records a snapshot for a manual checkpoint even inside the window`
  验证 ⌘S 绕过窗口。
- 服务端 `does not write anything when the bytes are unchanged`：同内容 `PUT` 返回原版本号，
  `current_version` 与快照行数都不变。
- 调度器单测 5 条（防抖、空转不发、地板间隔、`flush` 越过地板、`cancel`），草稿合并单测 4 条。
- 全量 `pnpm playwright test` 32 通过 / 2 失败，两个失败在 HEAD 上即存在（`editor.spec.ts` 的
  图片 strict-mode 与选区对齐），与本功能无关。

**代价与已知限制**

- IndexedDB 在隐私模式、存储配额耗尽或被浏览器清理时会静默降级；此时只剩服务端层，丢失窗口
  变成最多 3 分钟。该降级路径未在真实浏览器里验证。用户验收时豁免（waived by user, 2026-11-19）。
- 本地草稿把书正文写进浏览器存储，同机其他进程可读。自托管内部使用可接受。
- 自动保存会推进 `books.updated_at`，书库按更新时间排序的位置会随编辑移动。
- 20 秒 + 3 分钟地板的组合意味着「换设备接着写」最多丢失最近 3 分钟。
- 「十分钟窗口内不新增快照」的断言只有服务端测试覆盖，未在真实浏览器里手工复核；
  用户验收时豁免（waived by user, 2026-11-19）。
- 自动保存与 ⌘S 可能并发：靠 `saving` 标志串行，但两个标签页之间仍只由 `ETag` 保护。
